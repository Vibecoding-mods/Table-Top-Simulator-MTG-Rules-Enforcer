# Pooled effect rigs bring Arena feel cheaply

To get an MTG Arena feel on the TTS Commander table, build a small, fixed pool of pre-loaded AssetBundle "FX rigs". Each rig is a Shuriken particle system plus a sound, started from Global Lua with `AssetBundle.playTriggerEffect(i)`. Underneath that, add a layer that needs no assets at all: `highlightOn(color, duration)` pulses and pre-declared Global/Object XML UI tweens for banners and floating numbers. These mechanisms are close to free for the host. Triggering an effect is one Lua call and one network message, and particles render on each client's GPU. The one large CPU cost on this table is creating and destroying objects: **every `destruct()` costs about 360 ms**, so effects must never be spawned per event. The legal answer is just as clear. **Ripped MTG Arena audio is not allowed** under the MTGA EULA, Wizards' Terms and the Fan Content Policy. **Unity Asset Store and Fab packs, free ones included, cannot go into a public GitHub repo.** They are a grey area even when compiled into a public AssetBundle, unless the publisher gives written permission. That leaves one clean pipeline for a free open-source project: CC0 or CC-BY sounds (Kenney, the Cockatrice CC0 card pack, Freesound filtered to CC0/CC-BY), layered into original SFX, plus our own Shuriken effects built on CC0 textures such as Kenney's Particle Pack. On per-event design, Arena's documented lesson is about timing more than spectacle. Wizards repeatedly cut effects that block play to about 0.25–0.4 s and sped up high-frequency animations. So we should copy Arena's rhythm and tiering, not its art. The first thing to build is a two-client sync test, because no TTS document says whether trigger effects, highlights or bundle sounds replicate to clients.

## Five mechanisms, one cost that matters

TTS gives a rules engine five ways to add effects. They differ sharply in what they can show and what they cost.

**AssetBundles are the only route to real particles, animation, lights and arbitrary sounds.** They are built in Berserk Games' modding Unity project, and the only behaviour they carry is the provided `TTSAssetBundleEffects` component. **Custom C# scripts are not allowed** ([TTS KB](https://kb.tabletopsimulator.com/custom-content/custom-assetbundle/)). The component holds lists of looping and trigger effects. Each effect can toggle GameObjects on, play `ParticleSystem`s, play one `AudioClip` with a `Positional3D` flag, and run a legacy Animation or Animator state. Trigger effects have a `Duration` that defaults to 1 s ([TTSAssetBundleEffects.cs](https://github.com/Berserk-Games/Tabletop-Simulator-Modding/blob/master/Assets/Scripts/TTSAssetBundleEffects.cs)). Lua starts them by 0-based index through `getTriggerEffects()` and `playTriggerEffect(index)` ([API: AssetBundle](https://api.tabletopsimulator.com/behavior/assetbundle/)). With no scripts, an effect cannot take parameters at runtime. Each colour or intensity variant has to be its own pre-authored trigger index, and position and scale come from moving the rig object.

The render pipeline narrows the options further. A local check of the TTS install found Post Processing v2 and the particle module, but **no URP, HDRP or VFX Graph runtime assemblies**, so TTS runs Unity's Built-in pipeline. VFX Graph has not supported the Built-in pipeline since package 10.4 ([Unity Forum](https://forum.unity.com/threads/vfx-graph-support.1242217/)). In practice every effect must be Shuriken, using built-in `Particles/Standard Unlit` materials. The KB warns that custom, legacy and mobile shaders "often appear pink on other platforms" and asks for DXT1/DXT5 textures ([TTS KB](https://kb.tabletopsimulator.com/custom-content/custom-assetbundle/)). The Unity version also needs pinning down. The KB and the modding repo specify **6000.0.62f1** ([ProjectVersion.txt](https://raw.githubusercontent.com/Berserk-Games/Tabletop-Simulator-Modding/master/ProjectSettings/ProjectVersion.txt)). The installed `UnityPlayer.dll` reports **6000.3.10f1**, which matches v14.2's "Unity 6.3.10 LTS" target ([Patch notes v14.2](https://tabletopsimulator.com/news/patch-notes/v14-2)). No source says which build version is safest, so this goes into the first test round.

**Sound has no general-purpose Lua call.** There is no `playSound(url)`. The usable paths are a `TTSSound` inside a trigger effect, `TTSAssetBundleSounds` (which replaces an object's pick-up and collision sounds), the built-in spawn sound, and the single shared MusicPlayer. The MusicPlayer streams from URLs, waits until every player has loaded a clip, and has no volume API ([API: MusicPlayer](https://api.tabletopsimulator.com/musicplayer/)), so it is unsuitable for low-latency SFX. Every Arena-style sound must therefore live in a bundle trigger effect. Each player sets their own volume in game settings, and Lua cannot change it.

**Highlights and tints are the cheapest effect.** `highlightOn(color, duration)` turns itself off after `duration` seconds, and `setColorTint` recolours an object ([API: Object](https://api.tabletopsimulator.com/object/)). A 0.6 s pulse costs one host call and needs no cleanup. The catch is colour. The table already uses green for playable, red for attacker, blue for blocker and purple for an ability on the stack, so any new highlight must be brief or use a colour that doesn't clash.

**Global XML UI supports simple tweens.** These are Grow/Shrink, Fade and four-way Slide, with an `animationDuration` (0.25 s by default) and show/hide delays ([API: UI attributes](https://api.tabletopsimulator.com/ui/attributes/)). Per-player visibility lists and `raycastTarget="false"` for overlays that should not block clicks are also available. `UI.show`/`UI.hide` play the animations, and `setAttributes` batches changes. `setXml` rebuilds the UI asynchronously, so it should never run during play ([API: UI](https://api.tabletopsimulator.com/ui/)). Global UI is always flat 2D. Object UI renders in 3D but does not occlude, which suits a floating "−5" placed above a card on a rig object.

**Camera control is too blunt for effects.** The only tools are `lookAt`, `attachCameraToObject` and `setCameraMode`, and there is no shake API ([API: Player](https://api.tabletopsimulator.com/player/instance/)). Faking a shake would hijack four players' cameras. Leave it out, or make it opt-in.

| Mechanism | Host Lua cost | Client cost | Main risk |
|---|---|---|---|
| `playTriggerEffect` on a pre-loaded rig | One call plus one message (negligible) | GPU particles, overdraw | Sync undocumented; first-play hitch if not warmed up |
| `setPosition` to move a rig | One networked transform | None | Avoid `setPositionSmooth` (physics, multiple updates) |
| `highlightOn(c, t)` | One call, auto-off | Outline render | Clashes with existing state colours; sync unverified |
| Global/Object UI `show`/`hide`/`setAttributes` | One replicated update | UI tween | `setXml` during play; first-show hitch unmeasured |
| `spawnObject` + `destruct()` per effect | Async spawn plus **~360 ms per destruct** | Bundle instantiate | Visible freezes; never do this |

That last row decides the architecture. Local PresentMon measurements put **each `destruct()` at about 360 ms**, and five in one frame at 1.8 s. The cause is Unity "Unloading unused Assets" passes that walk roughly 86,000 loaded objects. The same measurements show that debug Lua sent through the External Editor API (messageID 3) costs about 360 ms, while custom messages (messageID 2) cost nothing ([local measurement, tts-perf-facts.md](local measurement notes (not published))).

Three rules follow. Spawn the rigs once at load and never destroy them during a game. Send effect events from the engine over the custom-message bridge, never through tts-exec. Trigger each rig once while it is hidden during setup, so download, instantiation and particle warm-up happen before the first spell. TTS publishes no particle frame-cost data, so the GPU budget is a design choice rather than a measured fact. A reasonable budget is effects of 1–1.5 s or less, additive unlit materials, no real-time lights with shadows, and a cap on concurrent rigs. Arena's own players complain that animations eat the turn timer ([Wizards feedback](https://feedback.wizards.com/forums/918667-mtg-arena-bugs-product-suggestions/suggestions/50847896-time-to-do-all-actions-are-to-low-animations-and)), which argues for restraint anyway.

One further limit follows from replication. If, as v14.2's fix for "clients being unable to start looping or triggered effects" suggests ([Patch notes v14.2](https://tabletopsimulator.com/news/patch-notes/v14-2)), effects are networked object actions, then a host-triggered particle burst appears for everyone. A per-player "Effects: Off" setting can then hide only per-player UI. It cannot hide shared particles, unless per-seat rigs hidden with `setInvisibleTo` work, and whether hidden objects still emit sound is untested. The realistic design is a host-level effects tier (Full / Reduced / Off) for shared particles and sound, plus per-player settings for UI flashes and numbers.

## Arena audio and asset flips both fail the licence test

### Official Arena sounds are off-limits in every form

No Wizards document allows extracting or redistributing Arena client audio. The MTGA EULA grants a personal, non-commercial licence and says "You may not copy the Software", and "Software" covers all related content ([MTGA EULA](https://store.steampowered.com//eula/2141910_eula_0)). Wizards' Terms (December 2025) ban reverse engineering, decompiling and making derivative works of any part of the Games, and §6.2 bars using Game Content except as expressly permitted ([Wizards Terms](https://company.wizards.com/en/legal/terms)). The Fan Content Policy says "Don't use Wizards' Video or Music". It excludes "verbatim copying and reposting of Wizards' IP", and it gives the Terms priority in any conflict ([Fan Content Policy](https://company.wizards.com/en/legal/fancontentpolicy)). Sound effects are not named, but the EULA and Terms cover them as Software and Game Content. Re-editing a ripped sound produces a derivative work, so that is out too. The official set soundtracks sold through Arena and music services, such as *Neon Dynasty* ([Wizards](https://magic.wizards.com/en/news/announcements/kamigawa-neon-dynasty-official-soundtrack-2022-02-18)), are listening releases with no reuse licence.

Wizards does enforce. It sent letters that took Card Conjurer offline and hit proxy sites in 2023 ([Commander's Herald](https://commandersherald.com/proxy-wars-hasbro-strikes-back-against-their-fans/)). The larger exposure is not audio at all. The FCP bars using Wizards IP "in other games", even free ones, which arguably covers any rules-enforced MTG client. Forge, XMage and Cockatrice operate in a tolerated but unlicensed space. Staying free, unbranded and free of ripped Arena assets keeps this project inside that pattern. What we can copy legally is the *style*: a whoosh-and-shimmer cast or a low thud on damage, built from our own layers.

### Asset Store "asset flips" cannot live in a public repo

Repackaging Unity Asset Store or Fab effect packs into our mod fails on two counts. The Standard EULA lets an asset be distributed only "as incorporated and embedded" in a Licensed Product with substantial original content. It forbids letting users "sell, transfer, distribute, lease, or lend the Assets" ([Unity Asset Store EULA](https://unity.com/legal/as-terms)). Unity's FAQ adds that an asset is not "incorporated" if end users can extract it ([EULA FAQ](https://assetstore.unity.com/browse/eula-faq)). Support says assets cannot be redistributed "in a way that allows others to extract them" ([Unity Support](https://support.unity.com/hc/en-us/articles/34387186019988-Can-I-use-assets-from-the-Asset-Store-with-other-engines)).

TTS caches every bundle as a plain `.unity3d` file in `Documents/My Games/Tabletop Simulator/Mods/Assetbundles/`, and AssetStudio exists specifically to extract them ([AssetStudio](https://github.com/Perfare/UnityStudio)). Players also routinely copy objects out of Workshop mods into their own saves ([Steam discussion](https://steamcommunity.com/app/286160/discussions/0/2566437997133230000)). The verdict has three parts. **Store source files in the GitHub repo are not allowed**, whether the pack is paid or free. Compiled store effects inside our bundle are a **grey area**. A stand-alone shared "effects library" bundle **leans not allowed**. Fab's summary carries the same ban on standalone redistribution and on allowing "others to do the same" ([Fab licence summary](https://www.fab.com/cla)).

Precedent points the same way. WalBanger's "Effects: Lighting, Magic, Smoke, Fire" Workshop library, with about 15k subscribers and credits only to "the Original Creators", has been removed for violating Steam guidelines ([Steam Workshop](https://steamcommunity.com/sharedfiles/filedetails/?id=2554037089)). The reason was not given.

Store packs also fit TTS badly on technical grounds. Hovl-style packs ship custom shaders that the KB warns turn pink. Unity's free Particle Pack supports the Built-in pipeline only on 2021.3 and weighs 160 MB ([Asset Store](https://assetstore.unity.com/packages/vfx/particles/particle-pack-127325)). Gabriel Aguiar's packs are mostly VFX Graph. The only legitimate route for a store pack is written permission from its publisher, scoped to "compiled inside a free public TTS AssetBundle, source not published". Without that, use the packs as visual references only.

## Arena trims effects to a quarter second; copy the rhythm, not the art

Arena's published patch notes say little about how its effects look, but they are consistent about timing. Patch 0.09.00 cut the minimum time an opponent's spell stays on the stack from 1 s to **0.4 s**. It cut Thousand-Year Storm's VFX block from 1 s to **0.25 s**, and it made mana VFX play for the stack item they pay for ([devtrackers 0.09.00](https://devtrackers.gg/magic-arena/p/b545ab55-0-09-00-patch-notes)). Exile animations, especially exile as a cost, were later sped up ([MTGAZone](https://mtgazone.com/2021-01-30-patch-notes/)). Bespoke mythic animations have since been mostly dropped ([MTGRocks](https://mtgrocks.com/mtg-arena-update-trades-good-looks-for-gameplay/)). That article also reports an ambient battlefield effect, drifting sand, that hid five graveyard cards. The design rule that follows is that effects must not block play, high-frequency effects get the shortest treatment, and nothing may cover game state.

Some per-event detail is documented. Priority shows through an orange pass button and a phase strip whose current step lights orange. A **burning fuse** around the avatar warns of a timeout ([Hipsters of the Coast](https://www.hipstersofthecoast.com/2018/03/how-to-play-mtg-arena-the-in-match-screen/)). Stops are orange on your turn and blue on the opponent's, with sword, shield and explosion icons for attackers, blockers and damage ([MTGAZone](https://mtgazone.com/arena-hot-keys-and-interface-guide-simplify-your-game-with-these-easy-tricks/)). Targeting lines tint the card text to match. Summoning sickness has a persistent VFX. Life totals update separately for first-strike and regular damage ([devtrackers](https://devtrackers.gg/magic-arena/p/b545ab55-0-09-00-patch-notes)).

Other familiar details are not documented: enter-the-battlefield slams scaled by size, damage numbers, dissolve on death, shatter on counter, and sparkles on life gain. They are recollection only, and should be checked against gameplay video before anyone claims "this is what Arena does". The research also found no source saying whether Arena colours its generic cast effects by colour identity. The colour palette below is therefore our own design.

Arena offers no precedent for four players. Brawl, Ranked Brawl included (June 2026), is still 1v1 ([Cardsrealm](https://mtg.cardsrealm.com/en-tt/articles/mtgarena-announces-ranked-brawl-starting-june-23)). Hearthstone is the closest model for tiering by magnitude. Its screen shake scales with the attacker's Attack, at 6–7 and then 8+, and players can turn it off ([TV Tropes, secondary](https://www.tvtropes.org/pmwiki/pmwiki.php/HearthstoneHeroesOfWarcraft/TropesSToZ)).

A board with 100+ permanents adds one more requirement: **coalescing**. Same-type events within about 300 ms should merge into one effect scaled by count, such as a single "+N" badge, one token shimmer for the batch, or one mass-death burst for a board wipe. Low-tier effects should be dropped when the queue backs up. Per-tap mana VFX and a sound on every phase step would be noise. The 300 ms window is a design choice, not a sourced number.

The table assigns each event a tier. T1 effects always play. T2 effects play at Full and Reduced. T3 effects play at Full only. Colour tints run white gold-white, blue cyan, black violet, red orange-red, green leaf-green, colourless silver and multicolour gold. They are always brief particle bursts, never persistent outlines.

## Build plan: prove sync first, then ship the zero-asset layer

The order follows the risk. The biggest unknown is whether effects replicate, and nothing else matters until that is answered. The cheapest high-impact work, highlights and UI, needs no bundles. Art comes last, because it is the most expensive to redo.

| Priority | Deliverable | Contents | Exit criterion |
|---|---|---|---|
| P0 | Sync and toolchain probe | One throwaway bundle: a cube with 3 trigger effects (particle burst, 2D sound, 3D sound) and a looping idle at index 0; built in both 6000.0.62f1 and 6000.3.10f1; one Kenney CC0 sound | Tests T1–T5 below pass or have known workarounds |
| P1 | Effect bus in Global Lua | Engine → custom message (messageID 2) → queue with tiers, 300 ms coalescing, concurrency cap (e.g. 6 rigs), host tier setting Full/Reduced/Off, per-player UI toggle | Board-wipe replay produces one mass effect, no frame spikes |

| P3 | SFX secondary bundle | About 20–25 layered sounds from Cockatrice CC0, Kenney and Freesound CC0/CC-BY; WAV 44.1/48 kHz 16-bit mono masters in repo; Vorbis "Decompress On Load" in Unity; 2D for anything important; 2–3 round-robin audio rigs | Sounds overlap cleanly; CREDITS.md complete |

The 5 MB total and the 50–300 KB-per-effect budget are our own targets. They are set from the local cache, where most bundles are 30–71 KB and the largest is 17.7 MB, and they are not a TTS rule. Loudness should also be normalised, for example to about −16 to −18 LUFS, with UI pings 6–10 dB below gameplay hits. That is general mixing practice, not a sourced TTS figure.

The first tests, in order, all run on a test save with no game in progress. Pushing scripts with Save & Play reloads the last saved state and wipes whatever is on the table.

**T1, two-client sync.** Host and one client sit at different seats. Host Lua calls `playTriggerEffect` on a rig. Confirm the client sees the particles and hears both the 2D and 3D sounds, and measure the delay with simultaneous captures.

**T2, highlight and UI sync.** Run `highlightOn(c, 0.6)` and a `UI.show`/`UI.hide` banner. Confirm the client sees both, and that the highlight turns itself off on the client's screen too.

**T3, late join.** Set a looping effect, then join a second client. Check whether it sees the current loop state or index 0.

**T4, bundle version.** Load the 6000.0.62f1 and 6000.3.10f1 builds of the same bundle, and check shaders and sound on both. If anyone has a Mac or Linux machine, check for pink materials there.

**T5, performance.** Use the in-TTS autopilot and PresentMon `--timed`, with no tts-exec polling. Fire 20 effects in 2 s through the pool, and compare frame times and rewind-snapshot time with and without the rigs on the table.

**T6, per-player audio.** Make a rig invisible to one seat with `setInvisibleTo` and trigger its sound. If the hidden player hears nothing, per-player priority pings become possible.

**T7, re-trigger behaviour.** Fire the same trigger index twice within its `Duration`, to learn whether it restarts or overlaps. The answer decides how many round-robin rigs P3 needs.

## Conclusion

The best way to make the table feel like Arena is a well-timed feedback loop, not the most spectacular effect. Arena's own history moves away from spectacle: bespoke mythic animations were cut and blocking time trimmed to a quarter second. TTS's constraints point the same way. There are no scripts, no VFX Graph, a 360 ms penalty for every destroyed object, and no per-player control over shared particles. A four-player Commander table therefore needs something Arena never needed: an event bus that tiers, coalesces and caps effects. That bus is the core engineering asset. The particles and sounds are interchangeable content that plugs into it.

Licensing settles the content question for us. The only assets that can sit in a public repo are the ones we make from CC0 and CC-BY parts. That rules out any shortcut through Arena rips or Asset Store flips, and it also protects the project from the takedowns that have hit both fan MTG tools and repackaged effect libraries. The one unknown that could still change the plan is whether TTS replicates trigger effects and highlights to clients. Answer that with the two-client test before building any art.
