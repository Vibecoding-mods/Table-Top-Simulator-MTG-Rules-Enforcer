How the engine table works

The TTS table shows the game and takes your clicks. A small Node bridge translates. Forge, running through Manabrew, decides what is legal and plays the AI. Then the table redraws whatever Forge says happened.

The big picture

Required Optional On the internet

One click, start to finish

Casting Lightning Bolt at an opponent, end to end.

  1. YouClick Cast Lightning Bolt in your panel, then click the opponent's life counter.
  2. TTS tableShows it at once: the card moves and the life counter turns red as your target.
  3. TTS → bridgeSends your answer as a background web request (POST /msg).
  4. Bridge → ForgePasses the action and its target through the relay.
  5. ForgeChecks it is legal, puts it on the stack and lets the AI respond.
  6. Forge → bridgeReturns the new game state and the next question.
  7. Bridge → TTSSends the board, only the zones that changed, plus the question for your panel.
  8. TTS tableRedraws: cards move, glows update, and the next question appears.

Inside the host

Table script

engine-renderer.lua

  • Draws cards, piles, library and command zone from the engine's board.
  • Panel with the current question, phase bar, stops and game log.
  • Q/E on a card pays mana or attacks; clicking a card or life counter targets or blocks.
  • Glows: white = can act, red = attacking or targeted, blue = blocking, orange = can be targeted, purple = on the stack.
  • Auras and equipment at half size beside their creature.
  • Removed cards go into a hidden trash deck instead of being destroyed (no 360 ms pause per card).

Bridge

bridge/bridge.js

  • One engine seat per TTS player, plus Forge AI seats.
  • Questions become panel options, including web-slinging and other alternative costs, and ninjutsu stops.
  • Arena-style stops: you're asked only when you can do something.
  • Board updates send card details once and skip zones that didn't change.
  • Card pictures: the table's own images first, then Scryfall, plus a token-art search.
  • AI decks from empty seats or mtg aideck presets.

Performance rules learned the hard way

Measured with PresentMon in October 2026. These explain why the code looks the way it does.

Keep card picture numbers smallTTS's rewind snapshot cost grows with each card's CustomDeck number. Engine pictures count up from 3000. 12,517,809 → 25 ms per card; 100 cards froze the table 2.7 s every 10 s
Never destroy cards mid-gameEach destruct() triggers Unity's asset clean-up. Merging into a hidden deck is free. ~360 ms per card · 5 at once = 1.8 s
Unlock decks before adding cardsA locked deck silently refuses putObject. Unlock, put, and lock again a frame later.
Send less JSONTTS decodes JSON slowly, so card details go once and unchanged zones are skipped. ~12–20 ms per KB
Use the cheap message pathThe bridge's custom messages are free; the debug "run Lua" command is not. custom message 0 ms · run Lua ~360 ms
