# Stress catalog: what breaks at large N, besides tokens

Catalog only, 2026-11-16. **Status 2026-11-27: some of it is built since** (the number-scan cap `ENGINE_NUMBER_SCAN` 100000, the engine's checkpoint cap of 40 and the 4096-entry event ring, `EXTRA TURNS` past 99; see `docs/engine-changes.md` "engine stress caps"); the rest is still a catalog. It covers every system I could find that a big Commander game can push
past what the engine, the bridge or the table handle. Two areas are left out because other work owns them:
- tokens, the token cap, the runaway "Keep going / End in a draw" limits, the 999-item stack draw, the attack tax and
  tie offers: `docs/big-turns-2-spec.md`;
- trigger and token timing: `docs/big-turns.md` and the benchmark in progress.
Those docs are cited here only where another system leans on them.

Sources read: Forge and the harness in the patched build tree `tmp/eb-1119` (read only), `bridge/*.js`,
`tools/engine-renderer.lua`, `tools/make-engine-copy.js`, `table-scripts/`, and the node's `Dockerfile` and
`java_backend.rs`. Short names:
- **Session**: `forge-harness/.../host/ManaBrewInteractiveSession.java`
- **Controller**: `forge-harness/.../host/ManaBrewInteractiveController.java`
- **renderer**: `tools/engine-renderer.lua`

**Measured** (fake TTS on fengari, a scratch copy of `tests/bench_big_table.js`; times are relative, object counts are
exact). The base table has 146 objects. Each zone was tested with N distinct non-token cards in it:

| zone | N = 30 | N = 300 | where they lie at N = 300 |
|---|---|---|---|
| graveyard / exile | 1 pile object | 1 pile object | on the pile |
| battlefield (distinct cards) | +30 objects | +300 objects | inside the table (layoutRow squeezes them) |
| hand | +30 objects | +300 objects | in the hand zone |
| stack (distinct spells) | +30 objects | +300 objects | **up to x = 435** (the table is about ±60) |
| 30 auras on one creature | +30 objects | n/a | the k-th aura sits k − 2 units from its host, so the 30th is 28 units away |

Nothing threw an error at any size. The fake TTS draws no frames, so a spawn's hitch, a texture load and a hand-zone
relayout cost nothing in it. Those costs are real in TTS but have not been measured here.

## 2. What the engine does at a cap (the rules side)

- **#1 numbers:** nothing changes in the rules. The bridge offers the real range and the harness stops guessing at 99.
  999 is only the table's own limit when Forge sends "no limit".
- **#12 numbers past 2^30:** clamped. A clamped number still compares as huge, so "you win if you have 1,000 or more
  life" still works. Doubling something at the cap leaves it at the cap. In the rules this is a real number in the
  game, just bounded.
- **#2 and #4 macros:** the bridge only plays back answers Forge asked for, so the rules aren't touched. It stops on
  anything new.
- **#9 checkpoints:** the rewind list gets coarser. The rules aren't touched.
- **#19 hang:** a draw, the same rules outcome as an unstoppable mandatory loop (CR 104.4b). It is the only new draw,
  and it never happens while a question is open.

## 3. Build these 10 first

Ordered by risk times cheapness. The engine items (**E**) go together into the next image with the big-turns-2
protocol step.

1. **Number choices up to 999** (#1): bridge picker plus the harness X estimate. It fixes legal plays that are
   impossible today. S + S·E.
2. **Fold the stack on the table at 8 per caster, and cut the status text** (#3). S–M.
3. **Checkpoint cap of 40, thinning within a turn** (#9). It stops a long combat turn from crashing the node. S·E.
   Measure one snapshot's size first (#17).
4. **Saturating numbers at 2^30, shown as "∞"** (#12): one SafeMath in Player, Card, AbilityUtils and damage. S–M·E.
5. **Compact number display** on life, commander damage, counter badges and the extra-turn badge (#10, #21): "12.3K",
   "1.2M", "∞". S.
6. **Mana pool text "G×150" and chips "999+"** (#6). S.
7. **Attachment and linked-exile fans that fit, with a "+N" fold** (#5). S.
8. **Bigger event ring (4,096) plus log name lists of "8 and N more"** (#7, #11). S·E + S.
9. **"Keep the same targets ×N" for copies** (#4), built on the repeat-yesno code. M.
10. **"Repeat that ×N" loop macro, capped at 1,000** (#2). It is the biggest piece, and the most visible one in combo
    decks. L.

Measure before building (cheap, no Docker needed for some): #16 AI and auto-pay time on a 6 × 60 distinct board
(`BigTurnTimingTest`), #17 checkpoint copy time and size, #23 respawning a 300-card pile and #8 a 30-card draw in real
TTS (PresentMon).
